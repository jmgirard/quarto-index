# M05: Multi-chapter book support

**Status:** done (2026-08-17, PR #5 https://github.com/jmgirard/quarto-index/pull/5)

**Goal:** Make index marks work in Quarto book projects: one aggregated HTML index built from every chapter at the M04 marker's chapter, cross-file locator links, and the already-working PDF book path pinned by fixtures.

**Outcome:** A book renders each chapter in its own Pandoc process, so the shipped behavior appended a partial index to every chapter and none of them was the book's. `book_context` in index.lua now derives the chapter list and order from `book.render`, this chapter's source and output paths from `quarto.doc`, and the page-to-root depth from `quarto.project.offset`, all normalized to `/` separators; each chapter writes a versioned JSON record (levels, cross-reference targets, anchor ids, output href, marker flag) to `.quarto/quarto-index/<chapter>.qi.json`, and the marker chapter reads the store back through the current chapter list — so a dropped chapter's record can never contribute — and builds the one index with the existing entry-tree builder. Locators became full link targets (`mark_target`), so one builder serves both a single document's `#id` and a book's cross-page href; anchors are still assigned in every chapter. The LaTeX path is untouched: a PDF book is one merged document and already aggregated. Nothing about the store can break a render (IP2): the write is one guarded unit and a record is validated against a version and a shape before use, each failure costing that chapter's entries and saying so. Five cases are reported rather than guessed at — no marker anywhere (from the last chapter, the only one that can know), a marker in a book with no marks, a second marker chapter (first in book order wins), a marker with chapters after it (whose entries are one render behind and can link to dead anchors), and a book-shaped page whose metadata is missing. Fixtures: `examples/book/` (four chapters, one in a subdirectory, a term shared across three, a cross-file cross-reference, an unresolvable one, a mark in the marker chapter), `examples/book-nomarker/`, and `examples/book-order/` (marker first, a second marker, a space in a chapter filename). Suite: `hrefs` manifest rows and multi-file resolution in `tests/htmlindex.py`, a recursive one-index sweep, a store-footprint sweep with a positive control, a store-name pin, render-derived fixture-axis coverage, a book PDF check counting pages rather than printed tokens, and six hardening checks (second render, stale chapter, unreadable record, unwritable store, marker-not-last, duplicate marker) — 79 checks, 89 with `--self-test`, against 65 at the merge base. README gained `## Books`; DESIGN records the split back-end.

**Decisions:** milestone-local — the store lives in Quarto's own `.quarto/` scratch directory rather than a visible cache dir, so a book gains nothing to configure or ignore; a marker-less HTML book gets no index and one warning rather than an automatic append, because choosing the chapter is what the marker exists for; locator hrefs are written raw rather than percent-escaped, verified because Quarto normalizes a filter-emitted `later%20chapter.html` back to `later chapter.html`, matching its own links.
