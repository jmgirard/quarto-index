# M044: Retire the pre-release warning

**Status:** done (2026-08-26, PR #44 https://github.com/jmgirard/quarto-index/pull/44)

**Goal:** README and the site stop telling readers the marking syntax may change until the first tagged release, which shipped as 0.1.0 on 2026-08-26, and the acceptance suite holds every page a reader meets to that sentence's absence.

**Outcome:** The four-sentence pre-release blockquote is deleted from `README.md` and `site/index.qmd` with no replacement sentence. `README_PRERELEASE_STALE` in `tests/run-tests.sh` holds those four sentences as a labelled claim container, registered `absence`/`ALL` — the registry's `git ls-files`-enumerated domain, 20 tracked pages under `site/` plus README — with the pinned registry counts moved from (17, 14, 3) to (18, 14, 4). `claim_text` now writes the swept file list beside the concatenation, and `check_prerelease_absent` reads the count from it rather than re-enumerating, exiting non-zero on an empty container or a swept list under two files. Its `flat()` strips a leading blockquote marker per line before flattening whitespace, because the retired block was a blockquote: without it only the block's first sentence, the one occupying a whole line, could ever be found. `tests/sitecheck.py`'s `WARNING` constant, its presence clause requiring README to carry the warning, its `ok` line and its docstring line are retired. The M40 warning-removal plant becomes three restorations — the first sentence into README, into the site front page, and into the site front page re-wrapped across a line break at a different column — each rebuilt from the live run's own file list by `m44_restore`, which hard-fails if the target is not in that list or the restoration changed nothing. Suite at 693 checks. IP3 amended in place; the DESIGN Architecture sentence no longer lists the warning among README's contents.

**Decisions:** D-026 — IP3's pre-release clause stops naming the README, and the warning it names is retired (amends IP3). Milestone-local: the plan gate chose the `ALL`-domain absence container over an absence clause in `tests/sitecheck.py readme` over two hand-named files; the implement gate chose stripping the blockquote marker before flattening, over whitespace alone as AC1 words it.

**Review:** Docs plus executable surface at a user-facing tier, so the full three-lens fan-out ran. Blame-history found nothing undone — every deletion traces to D-026, which authorizes it by name. Prior-review found no prior-review evidence on either surface, contributing zero findings. Diff-bug returned seven ranked findings. All five criteria verified with fresh evidence: 4 sentences absent across 21 files swept, matching an independent enumeration; three planted restorations each shown red; the "names the restored sentence" half verified independently of the plants. Three findings rejected — AC1's wording against a normalization that only widens what can match, the previous pass's hygiene stamp, and a short line in DESIGN prose. Four filed to a new pre-release-container hardening row: the failure naming no file, only one of the four rows ever planted, two forbidden rows being generic sentences that are still true, and the plants asserting the container half of AC2's wording but not the sentence half.
