# M43: A version matrix renders the fixtures on the oldest supported Quarto

**Status:** done (2026-08-26, PR #43 https://github.com/jmgirard/quarto-index/pull/43)

**Goal:** The declared Quarto floor stops being an untested claim: a second workflow renders four fixtures on the oldest Quarto release that range admits, on the version the Pages workflow installs, and on Quarto's current release, and compares the HTML index each one emits.

**Outcome:** `.github/workflows/versions.yml` — `plan` (reads the pinned leg's version out of `pages.yml` rather than carrying a copy), `render` (per leg: Quarto + TinyTeX, `imakeidx` installed with the runner's own `tlmgr` against a named repository, poppler-utils, the four fixtures each extracted immediately after its own render, uploaded as `index-<leg>`, `fail-fast: false`) and `compare` (`if: always()`). Floor 1.4.549 and the `pages.yml` pin on every push; Quarto's `release` channel weekly and on `workflow_dispatch`. `tests/indexdump.py` reduces one rendered artifact to a comparable row form — HTML in locator-href form, PDF through `pdfindex.read` — failing loudly rather than printing nothing. `tests/versioncheck.py`: `legs` (the matrix per event), `compare` (every leg's HTML extraction against the pinned leg's, byte for byte, naming each fixture and leg pair and reporting the PDF extractions left uncompared), `floor` (the workflow's floor against README and `site/tests.qmd`). `tests/pagescheck.py` gained `version` over a `read_pin` split; `htmlindex.section_rows` gained `row()`'s `hrefs` flag. Suite at 690 checks.

Milestone-local: the extraction lives in its own module rather than as modes on the two readers; the HTML dump uses the locator-href row form, not the count form; the pinned leg's version is read at run time.
