# M11: Empty index levels never lose the entry

**Status:** done (2026-08-18, PR #11 https://github.com/jmgirard/quarto-index/pull/11)

**Goal:** An empty sub-entry level is dropped once, at the shared level-derivation layer, so a leading empty level can no longer hand makeindex a null field that silently destroys the entry.

**Outcome:** `drop_empty_levels` strips empty levels from a parsed `entry=` value before any back-end sees them, returning each survivor's original index and the depth the author wrote; `derive_levels` routes an all-empty value to the mark's visible text or to nothing, each with its own message; `sort_levels` picks its levels through the surviving indices, so a key is dropped with the level it was written for and the loss is reported. `nonempty_levels` and the empty-level skip in `clamp_levels` are gone as unreachable. Also fixed: a registry collision where every leading-empty entry shared the empty-string level path, so one mark's `sort=` silently filed four unrelated entries under it; and the double fold-depth warning on `entry="P!Q!R!"`. New fixture `examples/empty-levels.qmd` and suite block (manifest 1r: emitted arguments, compiled-PDF rows, letter-grouped HTML rows, warning counts, a brace-aware null-field scan, a back-end-against-back-end path comparison); `check_no_null_field` and `README_EMPTY_CLAIMS` added. Suite 164 → 182 checks.

**Decisions:** D-002 (an empty index level is not a level: the drop, the visible-text fallback, and sort-level pairing).

**Review:** Three-lens fan-out. Prior-review and blame-history lenses: no findings beyond a stale line-number citation (rejected as cosmetic). Diff-bug lens: 10 findings. F1 was a confirmed regression on entries with NO empty level — `sort_levels` read the last-declared position off the realigned sort list rather than off what the author wrote, turning positional filler into a declaration, losing a second mark's key and inventing a rival-key report; one defect return, fixed and guarded by a no-empty-level fixture pair proved discriminating by revert. F2, F3, F4, F5, F6, F9, F10 fixed; F7/F8 to a clustered ROADMAP row. F5's premise was corrected by direct probe: makeindex accepts a trailing `!` before an encap, so the described hazard does not exist, though the brace-aware scanner stands. Two self-inflicted defects caught in the same pass: a hand-listed parent exemption in the PDF check (now derived from the printed tree) and a duplicated warning constant.
