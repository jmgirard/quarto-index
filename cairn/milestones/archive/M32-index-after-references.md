# M32: An index follows the bibliography where the author puts it

**Status:** done (2026-08-24, PR #32 https://github.com/jmgirard/quarto-index/pull/32)

**Goal:** An author who wants the index after the references can have it, and the README says what to write.

**Outcome:** The filter is unchanged; the order is now the author's to set. Writing a `# References` heading, an empty `#refs` div, and the placement marker below them makes Quarto fill the div in place, so the marker still sits under the finished bibliography — `\printindex` after `\end{CSLReferences}`, the index section after `div#refs`. README's *Placing the index* section carries the recipe, why it works, what each back-end does, that writing no div changes nothing, and what the recipe costs in HTML: Quarto builds `#quarto-appendix` with `role="doc-bibliography"` and a **References** heading only when it appends the block itself, so the recipe writes its own heading. `examples/references.qmd` and its byte-derived twin without the div hold all of it, read by `tests/m32refs.py` (`derive`/`latex`/`html`) with the `afterword` section telling an index at the marker apart from one at the end of the body. KI3 kept and reworded to the residual gap; two follow-up rows added.

**Decisions:** two milestone-local. AC2's index half is guarded by id plus `htmlindex.index_section` identity rather than by class, because the generated section's classes are this extension's own and would assert its output against itself. GP6 traded: the order is asserted in the LaTeX Quarto writes, not a compiled PDF, the typeset-print gap being an existing backlog row.
