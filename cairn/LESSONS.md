- 2026-08-16 (M01): Inside `\index{}` LaTeX reads under `\@sanitize` (`\` becomes catcode 12, so `\{` escapes nothing), and hyperref rewrites the argument at its first `|` before makeindex runs. Neither is discoverable from the character alone.
- 2026-08-16 (M02): makeindex parses `!` and `@` inside the encap argument too, so a cross-reference target needs the same quoting an entry key does — braces do not shield it. An unquoted `!` there is rejected outright, which under Quarto means a failed build rather than a lost entry.
- 2026-08-17 (M03): An anchor id must never sit inside content a renderer copies elsewhere — Quarto copies heading inlines into the sidebar TOC, duplicating any id inside. Emit anchors on empty elements adjacent to the copied content; borrowing a container's id makes every new shape (author id, second mark, missing id) another special case.
- 2026-08-17 (M03): `<span id=…>` written inline in markdown is nativized by Pandoc into an AST Span, id visible to filters. A fixture probing genuinely raw HTML must use a `{=html}` block, or it exercises nothing.
- 2026-08-17 (M04): imakeidx's `\printindex` closes the `.idx` file it has just read, so an index printed mid-document silently drops every later `\index` — the entries go to the `.log` and the build stays clean. Its `noautomatic` option skips that close.
- 2026-08-17 (M04): Quarto emits `use_latex_package` as `\@ifpackageloaded{pkg}{}{\usepackage[opts]{pkg}}`, so options never reach a document that loads the package itself; and `\PassOptionsToPackage` registers options on an already-loaded package, which defeats an `\@ifpackagewith` check written to detect exactly that case.
- 2026-08-17 (M05): Quarto renders a book's chapters sequentially in book order, each in its own Pandoc process — `doc.meta.book.render` carries the ordered chapter list and `quarto.project.offset` the page-to-root path, so cross-chapter work needs no guessing about layout, only somewhere to leave data between processes.
- 2026-08-17 (M05): Quarto normalizes a link target — a percent-escaped href a filter emits reaches output unescaped, matching Quarto's own links — so escaping at the filter layer is a no-op rather than a safety net.
- 2026-08-17 (M05): `pandoc.system.make_directory` raises a Lua error rather than returning a failure, so an unguarded call aborts the whole render; the `io.open` beside it returns nil and err, which is why one of the two was guarded and the other was not.
- 2026-08-18 (M08; corrected M12): `doc:walk` on a Pandoc value traverses `meta` as well as `blocks`, so a document-wide walk reports things written in the title or abstract; `Block:walk` visits an element's contents and never the element itself, so a top-level container needs checking directly. Pandoc 3.10.2's `Block` walk DOES reach a footnote's blocks, so M08's extra `Note` handler double-counts — a traversal fact recorded as a code comment is a claim about one Pandoc version; re-probe it rather than inherit it.
- 2026-08-18 (M09): makeindex keys an entry on its sort field, so `X@X` and a bare `X` are one key — comparing emitted `\index` argument strings to find a collision splits pairs the tool merges, and comparing what each level actually files under is what reads the tool's own view.
- 2026-08-18 (M09): A report that quotes a value the code derived — a fallback filled in where the author wrote nothing — hands them a string they never typed and cannot search for; name the fallback as what it is.
- 2026-08-18 (M10): makeindex swallows a TRAILING null field (`\index{Moles!}` prints as the bare top-level term) while rejecting a leading one outright, so the two empty-level shapes fail in opposite ways and neither is evidence about the other.
- 2026-08-18 (M11): makeindex reads `!` before an encap as part of the encap, not as a level separator — `\index{Cats!|see{X}}` is accepted and prints `Cats`, where a bare `\index{!Cats}` is rejected outright. A null-field rule inferred from one of the two does not transfer to the other.
- 2026-08-18 (M11): makeindex falls back to the SORT key when a level's printed half is empty, so `\index{mmm@!Cats}` silently prints `mmm` as a parent term the author never wrote — accepted, exit 0, no warning. An entry surviving the tool is not evidence it survived intact.
- 2026-08-19 (M13; extended M56): The sort-key registry keys on an entry's printed level path, so a new fixture mark whose path matches an existing probe's silently attaches its key to that probe — `entry="Cats!"` turned a neighbouring `entry="!Cats"` probe's `\index{Cats}` into `\index{a@Cats}`. Give a new mark a term no other mark in the file indexes. Extended M56: the same collision runs one level up, over METADATA rather than marks. A new top-level key can collide with one Quarto writes itself — `labels:` looked free and is not, since Quarto injects a nine-key title-block map into EVERY document, so a new unknown-key report fired nine times on a fixture declaring nothing, on its first render. Before claiming a top-level key, render a fixture declaring none of it and read what the metadata already holds; namespace the key (`index-labels:`) rather than share one. Extended M57: the same render answers what the HOST already refuses. `languages.lua` stringifies `lang:` so a list or map reaches its syntax check as nonsense, but Quarto's YAML schema rejects every non-string `lang:` before the filter runs, so the guard covers a class that never arrives. Render the bad value first: what the host rejects for you is not yours to guard.
- 2026-08-19 (M14): A per-record field that only a warning reads is not a format change. Bumping the store version for it invalidates every OTHER chapter's record, so a single-chapter re-render drops their terms from the book index — a real loss traded for wording. Make such a field optional with a named fallback and leave the version alone.
- 2026-08-22 (M21): A per-chapter record that mixes what the author WROTE with what that chapter CONCLUDED is read in another process as though every field were raw. Three review rounds each produced one defect from that single conflation — the record's range end, then the book's pairing verdict, then the record's role — each repaired on the path it was found and left standing on its sibling. Where a record crosses a process boundary, give the author's own values and a reader's conclusions separate names, or the next fix finds a new field to be wrong in.
- 2026-08-22 (M22): A LaTeX auxiliary file outlives the source that wrote it (`latex-clean: false`, or a failed render), so every command the filter writes into one is an input to the NEXT render — a render whose marks no longer define it. The `.aux` is read at `\begin{document}`, so a stand-in only acts from the preamble whether or not an index is printed; the `.ind` is read later, at `\printindex`, so only a document that prints an index can ever read a stale one (corrected M31, which covered the `.ind` too).
- 2026-08-24 (M29): A PDF book is ONE Pandoc process over the concatenated chapters, where an HTML book is one per chapter — so a position or ordinal a chapter's own render reports is a different number in the PDF render of the same book (blocks 8 and 5 against 26 and 34 here). An expectation written as "unchanged across the two formats" is unsatisfiable; only the parts that genuinely cannot move may be pinned.
- 2026-08-24 (M30; extended M33): A PDF's text layer does not hand back what the source carried. In a T1 text font `'` and `` ` `` extract as the right and left single quotation marks, and an index entry for `,` sits against the index style's own delimiter comma, which `,,` ligatures into a single `„` with the page number run up against it; and the layer renormalizes Unicode in BOTH directions — a decomposed `e`+U+0301 extracts precomposed, a precomposed Greek U+03CC extracts decomposed — so byte equality between a source term and its extracted entry is unsatisfiable the moment combining marks are in scope. Compare in NFC, and state an expected-extraction table from the typesetting fact behind each row, in precomposed form: a table filled from what the artifact under test returned is an oracle blind exactly where it was derived.
- 2026-08-24 (M31): TinyTeX ships RESTRICTED shell escape, whose whitelist includes makeindex, so imakeidx re-runs it mid-compile and rebuilds the `.ind` before `\printindex` reads it — a stale-index hazard passes silently on this machine while staying live wherever shell escape is off. `-no-shell-escape` holds the file stale, and asserting it byte-identical after the run is what proves the probe read the stale one.
- 2026-08-24 (M31): A stand-in for a command that PRINTS one of its arguments must pass that argument through, not gobble it. A gobbling stand-in for a locator command turns a stale index into one with no page numbers in it: a render that builds and lies, where the point of a stand-in is a render that builds and tells the truth.
- 2026-08-24 (M33; corrected M34): Quarto's default PDF engine is not pdflatex — on 1.10 it is lualatex — so the loud pdflatex stop is a signature an author reaches only by opting into pdflatex, and a document that sets a non-Latin-1 `mainfont` and leaves `pdf-engine:` alone gets whatever that default gives it. What that is depends on the font, not the engine: under `stix` the render exited 0 and corrupted `Việt`, under STIX Two Text it exits 0 and prints every term. Read the printed index, never the exit code.
- 2026-08-24 (M33): xelatex prints a precomposed character its main font lacks by falling back to that character's canonical decomposition, so `Missing character` fires in the log on text that typesets perfectly and stays silent on nothing. It is not evidence of a dropped glyph — the printed index is.
- 2026-08-24 (M34): Flipping a control check from an absence assertion to a positive one silently drops whatever the absence was discriminating. The no-engine control asserted `Việt` missing, which only that engine-plus-font pair produced; asserting every term present instead is true under any engine that draws the script, so the control stopped pinning the engine at all. When a control's expected state changes, ask what the old assertion could tell apart that the new one cannot, and assert that separately.
- 2026-08-25 (M36): TeX ends a failed run with `!  ==> Fatal error occurred, no output PDF file produced!` — a complete error report on ONE line that no `l.<n>` echo ever closes — and in the pdflatex control's log it is also what closes the inputenc report above it. So a log reader that requires an explicit close depends on what the log happens to end with, while one that closes an unclosed report at end of file reads the chatter after it as part of that report. Neither is free: pick which way to be wrong and say so where the reader is defined.
- 2026-08-25 (M36): Python's `str.isdigit()` is true of digits in EVERY script and `int()` reads them, so a guard written as `level.isdigit()` takes `'٣'` as level 3 — a value no caller writing the suite's own specs by hand can have meant. A guard over a hand-written domain names the spelling it accepts (`isascii() and isdigit()`), never the language predicate that happens to sit near it.
- 2026-08-25 (M37): bash suspends errexit inside a subshell that sits in an `&&`/`||` list even when that subshell sets `set -e` itself, so `( set -eo pipefail; f ) && rc=0 || rc=$?` runs `f` in exactly the shielded context such a check exists to escape — and is green on the very defect it tests for. Background the subshell and read its status with `wait`: only `wait` is then in the `&&` list, and the call itself is unshielded.
- 2026-08-25 (M37): under `set -u`, bash 3.2 (macOS, what this repo runs) errors on `"${A[@]}"` for an empty declared array while bash 4.4 and later expand it to nothing. A reachability or non-emptiness argument resting on that behaviour is true only on one of the two shells, so argue it from something the check itself pins — here, self-test plants that each name one of the listed lines and could not go red over an empty list.
- 2026-08-25 (M38; extended M073): When a judgement's scope narrows, the message reporting it goes false in silence — and a grep key chosen for stability hides exactly that. Keying the dangling-target check on the invariant tail (`indexes; a reader following...`) meant the clause that went wrong, "in this document", was the one clause no check read; three rounds of green suites shipped a report telling authors to mark a term they had already marked. When a change narrows what a check or a rule is computed over, re-read every message that names that set, and pin the varying clause somewhere, not only the stable one. Extended M073: comments enumerating that set are messages too — a closed three-item list of record states, in three files, went false when a change added a fourth.
- 2026-08-26 (M39): `tests/scans/m15-joined-messages.py` balances parentheses from every `warn(` in raw Lua source, comments included, so a COMMENT writing the bare token `warn(` with no closing paren swallows the rest of the file and reads the next file's messages as part of one message. Only `--self-test` caught it, because the moved tree it builds reorders which file follows which. In prose about the call, write `warn()`, never the bare `warn(`.
- 2026-08-26 (M41; extended M44, M45, M52): A residue sweep that greps a rendered page's MARKUP for its plumbing string goes false the moment some page legitimately prints that string as content a reader is meant to see — the gallery shows a fixture's source, and the fixture forges `data-qi-pending` in its prose, so the sweep reported a code block as filter residue. Ask the parsed page whether an element CARRIES the attribute; that is the promise, and a substring search was only ever standing in for it. The same blindness runs the other way: a comparison that flattens WHITESPACE does not see the markup the prose was wrapped in. Holding a retired blockquote's sentences against a page, whitespace alone finds only the one sentence that occupied a whole line — every `>` opening a continuation line lands mid-sentence in the flattened text. Strip the wrapper per line before flattening, and plant a re-wrapped copy, which is the case flattening alone cannot see. Extended M45: the same applies to what a reader SAYS when it fails. A message naming one shape goes false the moment a second shape can reach it — an empty entry list sitting exactly where the reader looks was reported as a list that is not a direct child, because the branch fired on any list anywhere. Give each shape its own message, order them most specific first, and plant a page carrying two shapes at once: it is the only case that shows which one the reader reports. Extended M52: a second module re-implementing the same sweep does not inherit the fix — a `flatten` written fresh for a new check reintroduced exactly this blindness, latent only because no swept page carried a blockquote. And the re-wrapped plant discriminates only when the line break falls INSIDE the phrase: wrapped anywhere else the `>` lands between two words the phrase does not span, the unstripped comparison still finds it, and the plant passes either way. Break the input where the normalization acts, and show the plant passing the pre-fix comparison before trusting it.
- 2026-08-26 (M42): A GitHub Actions workflow's own fields do not mean what their names suggest. `github.ref_name` is the TAG name on a tag push, so a deploy gated on `ref_name == <default branch>` publishes from a tag named after that branch — gate on `github.ref` against `refs/heads/<name>`. A job-level `permissions:` block REPLACES the workflow-level one rather than adding to it, so a job granting itself two scopes silently loses `contents: read`; restate every scope the job needs. A workflow-level `concurrency:` group serializes every branch's run against every other, where only the leg with a single target — the deploy — needs it; put the group on that job. And `quarto install tinytex` asks the GitHub API which release is current, unauthenticated, so it answers 403 when several runs start together — pass the run's own token. A bare `on: push` also matches TAG pushes, so preserving a probe commit as a tag fires the whole build on a commit planted to fail; a ref outside `refs/heads` and `refs/tags` (`refs/probes/*` here) keeps the commit reachable and triggers nothing.
- 2026-08-26 (M43): Rendering the fixtures on an OLD Quarto is not that Quarto's whole toolchain in miniature. Quarto 1.4.549's on-demand TeX installer answers `compilation failed- no matching packages` for `imakeidx.sty` against today's TeX Live, so the packages a fixture loads are installed with the runner's own TinyTeX before any render — and on EVERY leg, or the legs differ in more than their Quarto version. `tlmgr` is not on PATH (`quarto install tinytex` puts the tree under `~/.TinyTeX` and Quarto locates it itself, and TeX Live's platform directory is named differently across releases), it refuses to install anything until `update --self`, and `mirror.ctan.org`'s redirect can hand two jobs different mirrors, one stale enough that `tlmgr` refuses to run — name the repository. Extended M51, restoring these steps: `TLBIN=$(find ... | head -1)` under `set -o pipefail` fails the whole step when the tree is missing, so the explicit `-z` check below it never prints, and `head` closing the pipe can redden a good install — let the capture fail into empty (`| head -1 || true`) and let the named check do the failing. And a step restored verbatim from the commit that deleted it is stale against whatever the fixtures did since: the book extraction came back asking for a heading named `Index`, which the book has not printed since M49 gave it two named indexes, and only a dispatched run said so.
- 2026-08-26 (M43): A GitHub Actions job that must report over PARTIAL results needs `if: always()`: `needs:` gates on success, so `fail-fast: false` keeps the other legs rendering and uploading and then the job that says whether they agreed never runs. And a step capturing a reader's stdout into a variable swallows that reader's own failure message — under `set -e` the step dies with the reason sitting unread in the variable, so either write the diagnostic to stderr or print the capture before exiting. Extended M45: the same shape appears inside a reader. A line stating the size of the domain a clause swept, printed only on the path where every clause passed, goes silent exactly on the red run where a reader needs to know whether the sweep was empty — print the domain before the verdict, and assert it on a planted red run, not only on the green one.
- 2026-09-03 (M073): bash reads a script lazily by byte offset, so editing `tests/run-tests.sh` while a run is in flight corrupts that run's own parse — a leg failed and then the shell reported a syntax error at a line the file no longer had, and only the second, unedited run said anything true. A run in flight pins the file: batch the edits until it ends. At 13 minutes green and far longer under machine contention, the temptation to fill the wait with edits is exactly the hazard.
