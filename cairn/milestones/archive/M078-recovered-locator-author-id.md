# M078: A recovered locator lands on the id its author wrote

**Status:** done (2026-09-05, PR #78 https://github.com/jmgirard/quarto-index/pull/78)

**Goal:** In an HTML book, a mark recovered from a chapter's source carries the Pandoc identifier its author wrote on it, so the index links to that passage rather than to the top of the chapter's page.

**Outcome:** `recovered_marks`'s `collect` captures `span.identifier` as the mark's `anchor` where non-empty, gated on `#surviving == 0` so a cross-reference mark still contributes no locator, and only from the blocks walk — which `collect` takes as its own argument via the thin `from_meta`/`from_blocks` wrappers, keeping the two walk lines adjacent for M070's swap plant. `mark_target` builds `<chapter>.html#<author id>` where an id was written and the bare page where none was; `page_locator` stays beside `anchor` as what says a recovered mark contributes a locator at all. No `STORE_VERSION` bump — `anchor` was already a validated record field. Fixtures: seven id-bearing forms plus two `abstract:` marks in `examples/book-placement/four.qmd`, one in `examples/book/sub/two.qmd` for the nested href. Three self-test plants (identifier dropped, front-matter id carried, gate removed); `M065_GAMMA_ROWS_PAIRED` added because the author ids made M065-AC4's carryrange plant visible for the first time. `fragments.py resolve` now sweeps every generated section of the blocked renders' index page.
