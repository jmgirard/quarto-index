# M48: The version matrix's readers say what they read

**Status:** done (2026-08-27, PR #48 https://github.com/jmgirard/quarto-index/pull/48)

**Goal:** Close the remaining M43 findings on the readers around the version matrix: the compared row's borrowed id, the duplicated pattern, the unbound identifiers, the control's short fixture set, and the swallowed failure line.

**Outcome:** `section_rows` writes the `id it follows` field in the count form only, so the href row the matrix compares no longer carries an id Quarto mints and an upstream wrapper change cannot read as this extension emitting a different index; the count form the M38 placement manifests read is unchanged. `EXACT` has one home in `tests/versioncheck.py`, imported by `tests/pagescheck.py`. `indexdump.py` gained `minted_carried`, holding the anchor and entry prefixes against the ids the render carries — the section id was already loud — so a renamed identifier fails naming it rather than dumping rows quietly. The four fixtures the matrix renders are one table in the suite, `html-index` among them for the first time; the same table drives the local dumps, the legs tree and a new `versioncheck.py fixtures` mode, which reads every `indexdump.py html` invocation in the workflow and the extraction each is redirected into and holds the two sets equal. `m43_dump` no longer sends the reader's stderr to `/dev/null`, and reads from `/dev/null` itself so the fixture loop's stdin cannot be eaten. The workflow header names the two narrow reads that check it and keeps D-011's refusal of a wider scan; `check_floor` states what it reads of the workflow and of each document, bounds its document test over digits and dots, and closes its handles. Suite 387 checks, self-test 703 (from 692).

**Decisions:** none.
