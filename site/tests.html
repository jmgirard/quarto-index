Tests

tests/run-tests.sh --self-test

The suite renders the examples to LaTeX, HTML, PDF, beamer and GitHub-flavoured markdown, and checks the output against hand-derived manifests. It needs TinyTeX (with kpsewhich on the path and TeX Live’s stix2-otf package installed, which the non-Latin-1 renders load by file name), makeindex and pdftotext, and fails loudly rather than skipping if any is missing.

The Quarto version matrix

.github/workflows/versions.yml renders four of the fixtures — html-index.qmd, named-indexes.qmd, demo.qmd and the book — on Quarto 1.4.549, the oldest release the >=1.4.0 range the extension declares admits; on the version the documentation site is built with; and, weekly and on demand, on Quarto’s current release. The HTML index each leg emits is compared byte for byte against the index the pinned leg emits.

Weekly and on demand — not on every push — the same run also renders demo.qmd and the book to PDF on each of those Quarto versions, and reads the printed index out of each PDF. That leg is red where a fixture typesets but prints no index. It is kept off the push path because it installs a TeX distribution and a package from a third-party repository, so its red can trace to upstream mirror state rather than to a commit.

No PDF is compared across legs. Two Quarto versions typeset through different TeX engines, and an engine difference lands in a PDF’s text layer, where a comparison would be red about the engine rather than about this extension. The byte-for-byte comparison is over the HTML index alone; what the PDF leg asks of each version is that an index printed at all. The acceptance suite above renders and reads a printed PDF index on every run, on one Quarto version.
