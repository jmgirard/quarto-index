# M073: A store report names the record it met as the record it was

**Status:** done (2026-09-03, PR #73 https://github.com/jmgirard/quarto-index/pull/73)

**Goal:** In an HTML book, a record no render has written whose chapter's source also cannot be read is reported as one no render has written rather than as one that could not be read, and a record file that decodes to a table carrying no version number this render recognizes is reported as one that could not be read rather than as one another version of this extension wrote.

**Outcome:** `store_read` gained a sixth store wording on its `never_written and rebuilt == nil` path (`WARN_STORE_NEVER_LOST`), with its own opening clause so the suite's grep key counts it and not the never-written recovery report; `warn-distinct.py`'s EXPECTED moved 83 → 84. The classification test at the top of `store_read` narrowed from `data.version ~= STORE_VERSION` to that plus `type(data.version) == "number"`, so a record decoding to a table whose `version` is absent, a string or a boolean takes the could-not-be-read wordings; `valid_record` was deliberately left unnarrowed, so usability is unchanged and only the report moves. That narrowing also moved where such a record is drawn — from the `builds or first == nil` report site to the inline branches, per reading chapter — carrying a refused chapter in that state with it. Suite: the `m069-lostsource` leg re-pointed, an undecodable-record-plus-broken-source leg over `examples/book-placement`, three version-form legs and two `one.qmd` count legs over `examples/book-extensions`, and four planted defects under `--self-test`. Site, changelog, and six new books-page claim-ledger rows (37 → 41 pinned).
