# M061: A book reports the index section it deferred, doubled, or can never place

**Status:** done (2026-08-30, PR #61 https://github.com/jmgirard/quarto-index/pull/61)

**Goal:** An HTML book whose index section is deferred, printed twice, or blocked by a chapter record that can never be written says so once, naming the index and the chapters it could not read.

**Outcome:** A chapter's stored record gained two optional fields carrying what it CONCLUDED rather than only what it saw — `adopted` (the indexes it built a section for, in declared order) and `unseen` (the chapters after it whose record this render could not use); both absent read as no answer at the unchanged `STORE_VERSION`, so a record written before them keeps its chapter's terms. `store_read` became one pass returning records, version-refused chapters and `unseen` together, splicing this chapter's in-memory record in at its own position; `later_recorded`'s second full walk is retired, and `record_for_reading` hands the aggregation a copy so `fold_undeclared` cannot write a folded index name to disk. `store_write` now takes a built record and runs after the placement is settled. The unplaced-section report reads the placing chapter's recorded adoption instead of re-deriving one, names that chapter and the chapters it could not read, and drops its promise that a further render would place the section. A new doubled-section report, drawn by the book's last chapter off the same recorded adoptions, names an index carrying a section in more than one chapter. `examples/book-placement/` gained `five.qmd` and a fourth declared index nothing marks; `site/books.qmd`, `site/placing-the-index.qmd` and `CHANGELOG.md` state both reports.

**Decisions:** none milestone-local. Plan gates recorded reporting the doubling over always sending an unnamed index to the book's last chapter; a fifth chapter in the existing fixture over a new fixture directory; and optional new record fields over a `STORE_VERSION` bump.
