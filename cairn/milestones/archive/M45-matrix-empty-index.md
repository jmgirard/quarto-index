# M045: The version matrix cannot agree about an empty index

**Status:** done (2026-08-26, PR #45 https://github.com/jmgirard/quarto-index/pull/45)

**Goal:** The two readers the version matrix compares through stop being able to pass on nothing — a page whose index section holds no entry, and a run whose PDF extractions never arrived.

**Outcome:** `tests/indexdump.py`'s `html_rows` now fails when an index section header carries no entry or letter-group row under it, naming each such section; the clause sits past the read, so it is reached by direct call and guards against `index_entries`' raise being removed. `tests/htmlindex.py`'s `index_entries` splits its no-entry failure three ways — a list that is not a direct child (reported first, so a page carrying both shapes names the nesting), an entry list holding nothing, and no list at all — where the empty direct-child case used to be reported as a misplaced list, which is false of that page. `tests/versioncheck.py`'s `check_compare` requires the baseline leg to carry at least one `*.pdf.txt` and every other leg to carry the same PDF fixture-name set, with its own message for a leg that rendered no PDF at all; the two domain-size lines print before the verdict, so a red run still says what it swept, and PDF findings report alongside an HTML content difference. Its header, its report lines and `site/tests.qmd` all say the PDF names are compared and the content deliberately is not. Under `--self-test`: five hand-written pages (one entry, empty list, no list, misplaced list, both shapes on one page), two direct-call row lists, and four hand-built legs trees; `m45_planted` asserts the `FAIL:` prefix the criteria word. Suite 693 -> 707 checks.

**Decisions:** none cross-cutting. Milestone-local: the implement gate widened Scope by `tests/htmlindex.py`, because the empty-entry-list message AC1 asks for is written there and re-deriving the section's shape in `indexdump.py` would be a second copy of it.
